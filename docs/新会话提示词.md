【第二步 环境（先照做，否则会误判）】
每条 Bash 命令开头都必须显式设置 PATH，否则 ls/grep/dirname 等 coreutils 全部 command not found：
export PATH="/d/Docker/App/resources/bin:/c/Users/ASUS/.workbuddy/binaries/PortableGit/versions/1.2.0/cmd:/c/Users/ASUS/.workbuddy/binaries/PortableGit/versions/1.2.0/bin:/c/Users/ASUS/.workbuddy/binaries/PortableGit/versions/1.2.0/usr/bin:/d/nvm/nodejs:/usr/bin:/bin"
要点：
- git.exe 在 PortableGit 的 cmd/ 而不是 bin/；docker.exe 在 D:\Docker\App\resources\bin
- 本机没有 curl、没有本地 PostgreSQL/psql，裸 python 也不在 PATH

  → 查库用 docker exec docmind-pg psql -U docmind -d <db> -c "..."（容器内有 psql）
  → 宿主侧读容器 psql 输出必须 subprocess.run(..., encoding="utf-8")：本机 locale 是 GBK、
    容器吐 UTF-8，默认编码解码会把中文读成乱码，让"查库核对"变成假失败（第 4 组实测）
  → docker exec <容器> psql -v k=v -c "SELECT :'k'" 里的 -v 会被 docker exec 吞掉（变量不替换），
    且 -tAc -v ... 中组合短选项 -tAc 会把后面第一个参数当成 -c 的值 → 别走 -v，
    要么全用整数拼，要么 docker exec -i psql < file
- **沙箱接管删除操作（第 5 组实测，代价 37 个用例变红）**：python 进程被注入 sitecustomize.py，
  把 shutil.rmtree / Path.unlink 换成"移入回收站"，并带**同一轮累计的删除计数守卫**（到 50 抛 SystemExit）。
  → 测试代码**不做收尾删除**；"没落盘"改用目录前后快照断言
  → 生产代码里的清理走 os.remove（未被接管）且尽力而为（失败只记日志）
  → 详见 docs/findings.md D-041
- **pytest 必须给 basetemp**，否则收尾清理撞上守卫会把进程掐掉、**汇总行整个丢失**：
  cd backend && .venv/Scripts/python.exe -m pytest -q --basetemp="../../uploads/_bt_$(date +%s)"
- **conftest.py 不能用 os.environ 覆盖业务参数**（OS 环境变量优先级高于 env_file，
  会让 test_config.py 的默认值断言变红）→ 改 patch get_settings() 的单例实例
- 仓库根 .venv（3.13.14）只用于生成验收语料，不要拿它跑后端
- 沙箱禁止写工作区外；依赖只能装项目内 venv
- docmind 栈已在跑：api / worker / beat / pg / redis / nginx 六容器（pg 宿主 5433、redis 6380、nginx 8080）

- 数据库已在 Alembic 0001：docmind 与 docmind_test 都有 5 张业务表；跑完 pytest 要用 alembic 验库前，
  先 DROP SCHEMA public CASCADE; CREATE SCHEMA public; 再 upgrade head（否则 upgrade 是空操作）
- 迁移的两个硬约束：backend/alembic.ini 只能写 ASCII（本机 GBK 读它）；测试库连接串从 .env 派生，别抄口令
