> **最后更新**：2026-09-12（第 3 组账号体系完工后 / 第 4 次交接）

【工程纪律（前三组踩出来的，务必遵守）】

- docker compose ps 报 healthy ≠ 对链路可用，凡"通了"的结论必须打真实请求验证
- **重命令（pip install / docker build / 大套件 pytest）一律后台跑**，别赌前台时限；
  被 SIGTERM 掐断 ≠ 没执行，事后必须用只读命令核实真实状态
- venv 若报 `ImportError: cannot import name X from Y (unknown location)` → 那是命名空间包遮住了真包
  （pip 被中断留下的空壳目录）；修复：mv .venv .venv.damaged → 用 D:\IDE\Python\Python312 重建
  → 装依赖（走缓存，别加 --no-cache-dir）→ 全量探测确认。Windows 上别用 --force-reinstall

  仅**首次**构建（缓存为空）仍需全量下载，那时慢是正常的；日志慢到 14 kB/s 是网络问题不是故障
- **写操作的端到端验收要等容器稳定再跑**，不要紧接在 up -d --build 之后
- 分块验收按「覆盖性 / 顺序性 / 忠实性」三项判断，不得用"拼接结果等于原文"（与 64 token 重叠矛盾）
- 探测函数别把异常压成只剩类型名——第 2 组就因此把 Event loop is closed 误判成"测试库不可达"
- 声称"跑绿了"之前先看汇总行有没有 skip

【模型网关】
单一网关：一个 BASE_URL + 一个 API_KEY 覆盖生成/嵌入/重排三个用途。
两个坑：重排必须走 RERANK_BASE_URL（DashScope 原生路径，compatible-mode 下 404）；
生成模型默认思考模式，max_tokens 太小时 content 返回空串。详见 docs/HANDOFF.md 第六节。
W5 全程不调用任何模型服务。

【汇报要求】
- 中文；结论先行，不要套话与模板化铺垫

- 每完成一组就回写 docs/progress.md 证据并勾选 tasks.md，不要堆到最后
