## Purpose

为平台提供账号身份与登录态，使知识与文档获得明确的归属维度，并作为所有内容接口的访问前提。

## ADDED Requirements

### Requirement: 账号注册

系统 SHALL 允许访客以用户名与密码注册账号。密码 MUST NOT 以可还原的形式存储。同一用户名 MUST 被唯一占用，重复提交 MUST 被拒绝；用户名 MUST 区分大小写（`alice` 与 `Alice` 是两个不同账号）。密码强度 SHALL 要求长度不少于 8 位且不超过 128 位，并同时包含字母与数字；两个长度阈值 MUST 可配置（默认 8 与 128）。

#### Scenario: 注册成功

- **WHEN** 访客提交未被占用的用户名与符合强度要求的密码
- **THEN** 系统创建账号并返回可立即用于登录的身份标识，响应中不包含密码或其摘要

#### Scenario: 用户名已被占用

- **WHEN** 访客提交已存在的用户名
- **THEN** 系统拒绝注册并给出可读提示，不产生新账号

#### Scenario: 密码强度不足

- **WHEN** 访客提交长度不足 8 位、超过 128 位、或未同时包含字母与数字的密码
- **THEN** 系统拒绝注册并说明具体不满足的要求

#### Scenario: 用户名区分大小写

- **WHEN** 已存在账号 `alice`，访客以 `Alice` 注册
- **THEN** 系统创建新账号，`Alice` 与 `alice` 互不影响（用户名不做大小写归一）

### Requirement: 登录与登录态

系统 SHALL 校验凭证并签发带有效期的登录凭证。所有知识库与文档相关接口 MUST 要求有效登录凭证。凭证失效后 MUST 拒绝访问并提示重新登录。

#### Scenario: 登录成功

- **WHEN** 已注册用户提交正确的用户名与密码
- **THEN** 系统返回该用户的登录凭证，可凭此访问内容接口

#### Scenario: 凭证不正确

- **WHEN** 用户提交错误的密码或未注册的用户名
- **THEN** 系统拒绝登录，且不区分"用户不存在"与"密码错误"

#### Scenario: 凭证过期或伪造

- **WHEN** 携带过期或无法验证的凭证访问内容接口
- **THEN** 系统拒绝访问并提示需要重新登录

#### Scenario: 未携带凭证

- **WHEN** 未携带任何凭证直接访问知识库或文档接口
- **THEN** 系统拒绝访问

### Requirement: 数据归属由登录态决定

系统 SHALL 将每个知识库与每份文档归属于唯一账号。请求身份 MUST 仅由登录凭证推导，MUST NOT 接受请求参数中声明的用户标识来决定归属。

#### Scenario: 归属取自登录态

- **WHEN** 已登录用户提交创建知识库或上传文档的请求
- **THEN** 新建对象归属该登录账号，请求体中出现的任何用户标识均被忽略

#### Scenario: 越权操作的响应不泄漏信息

- **WHEN** 用户以自己合法凭证尝试操作另一账号的对象
- **THEN** 系统拒绝该操作，且响应不包含对象内容
